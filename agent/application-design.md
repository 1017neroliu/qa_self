# Agent 应用设计与人工复核

## 从已有的标注平台出发

平台已有模型辅助标注功能，支持预标注开关、提示词配置和模型选择。争议样本质检可以复用这些能力。后端读取原文与各人的候选标注，模型按项目规范给出建议，审核员在页面上做最终复核。

| 决策 | 适合的实现 |
| --- | --- |
| 每次都需要原文和候选标注 | 后端固定读取，再传给模型 |
| 可以按项目和标签直接定位条文 | 后端可以预先加载相关规则 |
| 每条样本需要查的规范和边界案例不同 | 提供查询工具，由模型决定查什么、是否继续查 |
| 建议必须引用当前有效规范 | 后端限定项目与版本，校验引用，缺少依据时标记待人工判断 |

按需调用和业务约束可以同时存在。模型可以决定怎么查，后端可以规定什么样的输出才算正式建议。

## 让审核员看得出建议的依据

仅有评分或「依据第 3.2 条」难以复核。模型可以返回候选标签、规则 ID 和适用理由，后端根据本次提供给模型的规则回填条文和版本。

1. **核验引用来源。** 检查规则 ID 是否对应本次上下文中当前项目的生效规则。模型没有查询，后端也没提供规则时，可标记「依据未验证」。
2. **判断条文是否支持建议。** 审核员对照规则和原文判断。两条规则都可能适用时，分别展示候选标签、条文、适用理由和争议点。查到明确的优先级就一起展示，仍有冲突则交由人工裁定。

单次人工复核可以沉淀最终标签和复核理由。需要补充规范时，再用类似样本和边界样本确认适用范围，由规范负责人发布新版本。
